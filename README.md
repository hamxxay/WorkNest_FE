# WorkNest Portal (CMS)

Web app for [WorkNest](https://worknestpk.com), coworking spaces and private offices in Islamabad. It holds the staff portal (CMS), the customer area and a few public pages.

Live at **https://cms.worknestpk.com**. The public marketing site is a separate app (WorkNest-MainWeb) at https://worknestpk.com.

## Who uses it

| Area | Paths | Who |
|---|---|---|
| Public pages | `/`, `/gallery`, `/about`, `/contact`, `/book-a-tour`, policy pages, `/quotation/:id` | Anyone |
| Sign in | `/login`, `/signup` | Anyone |
| Customer area | `/my-bookings`, `/my-payments`, `/my-meeting-rooms`, `/my-agreements`, `/my-quotations`, `/checkout`, `/payment-result` | Signed-in customers |
| Staff portal | `/admin/*` | Super admin, admin, sales executive |

Roles come from the WorkNest API (`super_admin`, `admin`, `sales_executive`, `customer`):

| Role | Access |
|---|---|
| Super admin | Everything, including Space Config and Challan Validity |
| Admin | All of `/admin` except the super-admin pages |
| Sales executive | A subset of `/admin` (dashboard, KYC, quotations, agreements, lease templates, invoices, bookings, tour inquiries, complaints, WhatsApp, attendants and access users, network). The list is `SALES_EXECUTIVE_ROUTES` in `src/app/guards/admin.guard.ts`, used by both the guard and the sidebar. |
| Customer | Public pages and the customer area |

When roles were read only from browser storage, the admin guards confirm them with `GET auth/me` before opening an admin page, so edited roles are not trusted.

## Staff portal features

| Group | Pages (`/admin/...`) |
|---|---|
| Dashboard | `dashboard` (role dashboards, forecast, weekly report, access overview), `profile` |
| Sales | `customers`, `kyc`, `bookings`, `quotations`, `quotation-responses`, `agreements`, `lease-templates` (rich-text lease editor) |
| Inquiries | `contacts` (Tour Inquiries), `complaints`, `whatsapp` (WhatsApp inbox) |
| Finance | `invoices` (Invoices and Billing), `payments`, `pricing`, `reports/security-deposits`, `challan-validity` (super admin) |
| Spaces | `locations`, `spacetypes`, `spaces`, `manage-spaces`, `space-configuration` (super admin), `gallery` |
| Access control (Hikvision) | `attendants`, `biometric-users`, `staff-access`, `access-dashboard`, `access-activity-log`, `access-analytics` |
| Network (UniFi) | `network`, `network/clients`, `network/devices`, `network/device/:mac`, `network/internet`, `network/wifi` |
| Administration | `users` |

Hikvision machines and the UniFi console are never called from the browser. The app calls the WorkNest API (`/hik/*`, `/unifi/*`), which talks to the devices.

Customers pay at checkout through the API (PayFast, 1Bill voucher or card, see `src/app/services/`). No payment credentials live in this app.

## Tech

- Angular 21, standalone components, signals, zoneless (no `zone.js`), lazy-loaded routes
- TypeScript 5.9, RxJS 7
- Firebase Auth (email/password and Google sign-in), synced with the API's JWT
- Tiptap (lease template editor), Chart.js (dashboards), jsPDF and html2canvas (PDF export), anime.js
- HTTP interceptors in `src/app/interceptors/`:
  - `auth.interceptor.ts` adds `Authorization: Bearer <token>`, sends users to `/login` on 401, shows a notice on 429
  - `error.interceptor.ts` turns API errors into readable messages
  - `global-error-handler.ts` shows unhandled errors instead of failing silently

## Run locally

Requires Node.js 20 or later and a WorkNest API (WN_APIs) running locally, by default on http://localhost:5200.

```bash
npm ci
cp .env.example .env      # then fill in the values
npm start                 # generates environment.ts, then runs ng serve
```

Open http://localhost:4200.

### Configuration

`src/environments/environment.ts` is required. It is generated by `set-env.js` from `.env` (or from process environment variables in CI), and `npm start`, `npm run build` and `npm run watch` all regenerate it first. The `.env` file is ignored by git. Edit `.env`, not `environment.ts`, and never commit real keys.

| `.env` variable | `environment.ts` setting | Purpose |
|---|---|---|
| `API_URL` | `apiUrl` | Base URL of the WorkNest API, including `/api` |
| `FROM_EMAIL` | `fromEmail` | Sender address |
| `WHATSAPP_NUMBER` | `whatsappNumber` | WhatsApp number used by contact links |
| `PAYFAST_SANDBOX` | `payfast.sandbox` | `true` (default) or `false` |
| `FIREBASE_API_KEY`, `FIREBASE_AUTH_DOMAIN`, `FIREBASE_PROJECT_ID`, `FIREBASE_STORAGE_BUCKET`, `FIREBASE_MESSAGING_SENDER_ID`, `FIREBASE_APP_ID` | `firebase.*` | Firebase project for sign-in |

All variables except `PAYFAST_SANDBOX` are required; `set-env.js` stops with an error if one is missing.

`API_URL` options:

| Where | `API_URL` |
|---|---|
| Local, direct to the API | `http://localhost:5200/api` |
| Local, through the dev proxy | `/api` (`proxy.conf.json` forwards to http://localhost:5200) |
| Production | `https://aeo.eaccounting360.com.pk/WorkNest/api` |

## Build and deploy (cPanel)

Set `API_URL` in `.env` to the production API, then build with the production configuration:

```bash
npm run build -- --configuration production
```

The site is written to `dist/work-nest/`. Upload the contents of that folder, including the hidden `.htaccess`, to the domain's folder on cPanel (the document root of cms.worknestpk.com).

`.htaccess` comes from `public/.htaccess` (Angular copies it into every build). It:

- redirects `http://` to `https://` (301) and sends `Strict-Transport-Security` on HTTPS answers;
- serves `index.html` for app routes (without it, refreshing `/admin/bookings` returns 404);
- sends the security headers (`X-Frame-Options`, a minimal `Content-Security-Policy`, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`) and turns off folder listings;
- keeps `index.html` out of the browser cache and lets the hashed JS/CSS files be cached for a year.

After an upload, `curl -sI https://cms.worknestpk.com/` should show those headers; if none appear, `mod_headers` is off on the server.

The browser calls the API directly, so the API (WN_APIs) must list `https://cms.worknestpk.com` in its CORS allowed origins. If sign-in or any page fails with a CORS error in the browser console, check that setting first.

`vercel.json` is also in the repo for a Vercel deployment; cPanel does not use it.

## Project structure

```
src/
  environments/environment.ts   generated by set-env.js from .env
  app/
    app.routes.ts               top-level routes, all /admin routes and guards
    app.config.ts               router, HTTP interceptors, session restore on start
    pages/
      public.routes.ts          home, gallery, about, contact, book-a-tour, policies
      auth.routes.ts            login, signup
      user.routes.ts            customer area (my-*, checkout, payment-result)
      admin/                    staff portal: layout (sidebar), dashboard, manage
                                (shared list/edit page for most entities), kyc,
                                access, network, reports, ...
    guards/                     auth, user, admin (incl. sales executive), super-admin
    interceptors/               auth, error, global error handler
    services/                   one service per API area (auth, booking, quotation,
                                agreement, payment, kyc, hik-device, unifi, whatsapp, ...)
    models/                     admin, hik-device, unifi types
    components/                 navbar, footer, toast host, WhatsApp button, policies
    utils/                      dates, phone, CNIC, discounts, space assignment
public/                         favicon, images and .htaccess (copied into the build)
set-env.js                      writes environment.ts from .env
proxy.conf.json                 dev proxy for /api to localhost:5200
```
